Run `npm run dev`, then open <http://127.0.0.1:4173/>. This folder originally contained the approved media and specification without an existing framework or website source. The implementation therefore uses HTML, CSS, JavaScript and the native Web Animations API.

The studio is live at **https://after-hours-portfolio-virid.vercel.app/** on Vercel, in `vedansh-mehrotras-projects/after-hours-portfolio`. ## Interaction

- The room fills the viewport. Once the studio assets and CMS content are ready, the lamp automatically turns on after 3.5 seconds of visible room time, using `after_hours_transition_clean_2s.mp4` and handing off to the lit ambient loop. The delay pauses inside sections and while the tab is hidden. Clicking the lamp first takes priority. Clicking again switches immediately to the approved dark loop and keeps it dark until another click. Refresh starts a new visit. There are no discovery blinks or shade outlines. Reduced motion skips the activation clip. The localhost-only `reference=1` capture aid freezes the room and suppresses automatic lighting.
- Click the main monitor to enter Projects. The live CMS contains PathForge, ResolveFlow, Automated CI/CD Framework and PlanEase, with three cards per page and a fourth-project page. Each has a distinct SVG pixel emblem; the room artwork is unchanged. The fixture-only static test server still uses the original sample names and original illustration crops.
- Click the small green CRT beside the cat to enter About Me with the same smooth camera and pixel streaks. Back / Escape / browser Back returns to that monitor and preserves the room's lighting and framing. Portrait devices have an About Me shortcut when the CRT is outside the crop.
- Arrow keys and buttons select a card. Click a card to read its detail. Escape / Back returns detail → Projects → room, restoring monitor focus and lamp state.
- On portrait phones the wide studio fills the screen and can be dragged sideways. A Projects fallback button is provided. Inside Projects, swipe through the enlarged pixel cards.
- Query deep links such as `/?project=pathforge` work on refresh. `?view=projects` opens the selector.
- `?view=about` opens the profile directly and works on refresh.
- The pinned board opens Journey (`?view=journey`): hover, focus, or tap a photo to read its milestone. The five current chapters follow University → AirBorneHRS → Robotics Club → Think Computers → academic recognition. Six pins per page keep the complete board visible; up to 100 published milestones create additional pages. Missing photos use small pixel document cards; uploaded photos override them. The red thread follows their sort order. Room artwork stays baked and unchanged.
- The open journal left of the monitor opens Resume (`?view=resume`). Select a chapter to read the pixel typeset version. Its download control sits at the top right and serves the unchanged CV approved by the user. The PDF URL is independent of the chapter content.
- The phone beside the journal opens Contact (`?view=contact`). Name and reply email are optional; message is required. Drafts survive navigation within the page, failures retain the text, and success is shown only after a successful backend response. Refresh clears the in-memory draft. The contact interface exposes no phone number or recipient email.
- Contact uses `novalidate` and app-rendered errors below each invalid field, preserving server validation. Empty/short messages and malformed optional email addresses are rejected before sending. Error descriptions, `aria-invalid`, a live summary and focus on the first invalid field replace native browser validation popovers. Errors and drafts survive section navigation and clear as the field is corrected.
- All three use the approved smooth camera and shared rush effect. Each has portrait shortcuts, keyboard entry, Escape / Back / browser history, and reduced-motion behavior.
- Projects detail uses Overview, How it works, In pictures, and Stack & links. Short highlights, numbered process steps and three engineering notes replace long paragraphs. The gallery has captioned pictures, thumbnails, arrows and full-size links; stack entries have locally served colored icons. All content fields remain editable in admin. - The left bookshelf opens Certifications & learning (`?view=bookshelf`). Six AWS Educate training badges and the verified SDGAcademyX/edX Sustainable Development course have verification links. Four additional CV-listed courses remain private drafts pending credential details. The editor supports course certificates, skill badges, professional certifications, learning notes and optional certificate PDFs. The original `notes` CMS key is retained for compatibility.
- Object hit areas and hover/focus contours follow the artwork's shapes. Compact pixel captions replace native title tooltips. `STUDIO_INTERACTION_NOTES.md` records the implemented corrections, lamp behavior, cursor sprites and sound palette.
- Visible contour SVGs are siblings of the clipped hit buttons, preserving the full thin stroke. Journal and book hit bounds are calibrated separately from their existing camera focus rectangles. The lamp uses a curved shade/rim contour; books follow the uneven spine heights. After the lamp's first use, keyboard focus uses a small marker and caption rather than outlining the entire shade again.

## Sound and contextual cursors

`audio.js`, `cursor.js` and `feedback.css` add feedback with native browser APIs and no new dependencies. The original studio images, videos and camera geometry are unchanged. The cat gets a source-coordinate hit area, an accessible name, a compact caption, a petting-hand cursor and an optional purr; its artwork is not redrawn.

- Sound defaults to ON. To respect browser autoplay restrictions, AudioContext creation and recording requests begin on the first real click/touch or meaningful keypress. The SOUND button can mute before playback starts; explicit mute/on preferences and independent rain/effect levels persist in local storage. A new page still waits for browser interaction before starting playback.
- The sound control stays available in every section, including keyboard focus traversal. Escape closes volume settings before leaving the section. On phones the control collapses to an icon; headers reserve its space.
- Rain uses an indoor recording, filtering and a tail/head loop crossfade. Both recordings are normalized after filtering, with peak headroom. Purr filtering emphasizes the audible texture above its very low bass so small speakers can reproduce it more clearly. Purr playback is at most 2.2 seconds and has a 3.2-second cooldown. Clicks are moderately louder; zoom swells have a stronger short envelope. A shared soft ceiling protects combined peaks. Mute stops all voices and pending purrs. Page visibility suspends playback and resumes it only while enabled. The first pet can wait briefly for recording decode without stacking cues.
- Object cues: mouse click for Projects, mechanical/blip for About, switch for lamp, paper tap for Journey selections, shuffle for board pages, page turn for changed journal chapters, book/paper for Notes, phone tap for Contact, and two soft notes only after an accepted send. Hover is silent. Camera swells are very quiet, skipped for reduced motion and canceled with interrupted motion.
- `assets/audio/CREDITS.md` and `sources.json` record the two CC0 sources and file digests. `scripts/fetch-audio.py` downloads them; runtime audio is entirely same-origin. Other effects are synthesized in project code rather than labelled as physical recordings.
- CSS uses original pixel arrow, point and grab SVGs with native fallbacks. Only pet and pending-work cursors use a pointer-transparent animated sprite. Text keeps its native I-beam; touch and forced-color modes retain system behavior. An hourglass appears over a genuinely pending contact form, never during the camera animation. No artificial loading delay or loading screen is introduced.
- Build the small original UI sprites with `python scripts/build-cursors.py`. No image generation or room artwork processing is involved.

`qa/feedback-review.html` includes actual-size cursor previews, desktop/mobile captures and a recording of the browser's rain/purr mix. Refresh it with `node scripts/capture-feedback.cjs` while the server runs. Audio output is checked through the actual Web Audio analyser; automated signal checks do not establish subjective sound quality. The preview is provided for listening and mix review.

`qa/journey-release/` contains the latest automatic-lighting recording, desktop/mobile Journey screenshots and verification report. Run `node scripts/verify-journey-lamp.cjs` against the development CMS, or set `DEPLOYMENT_URL` to the release origin for read-only production verification. `qa/audio-lamp-review.html` retains the earlier sound mix and inline-validation review; its bulb-blink recording is historical and was replaced by automatic lighting on 23 October.

Camera and section viewport tests save screenshots in Playwright's per-run `test-results/` directories. Dedicated capture scripts maintain the browsable review images in `qa/`. This avoids test workers overwriting older review assets, which produced Windows file-open failures on this host. No UI assertion was removed for that adjustment.

`about.js` contains the editable starter profile and an `aboutRepository.getPublished()` boundary. Its copy uses the supplied AI/ML undergraduate background and has no invented contact details or credentials. The green monitor and destination use the same record and markup. ## New section content and backend boundary

`content.js` supplies `journeyRepository.listPublished()`, `resumeRepository.getPublished()`, `notesRepository.listPublished()`, and `contactRepository.send()`. `sections.js` renders the physical-object destinations; it declares their source-coordinate rectangles once. Journey, resume and notes exclude drafts and have missing/error states. Photos are referenced by URL and alt text. Journey uses stable IDs, sort order, results and descriptions; its strings follow chronological sort order. The room board, journal, phone and bookshelf have no live content overlays.

`cms.js` supplies the production read adapters and a session-protected draft preview. `admin/`, `api/admin.js` and `server/content.cjs` provide editing, validation, optimistic revision checks and publication snapshots for every content section. Media uploads are private until referenced by published content. Public reads never return draft records. About has no resume or Journey tabs.

`api/contact.js` uses the [Resend HTTP API](https://resend.com/docs/api-reference/emails/send-email), with no mail SDK dependency. It validates message fields and request size, rejects the honeypot, checks the configured origin, and accepts only the server-configured recipient. `server/contact.cjs` adds durable Postgres rate limits, duplicate suppression and provider idempotency. `.env.example` lists server-only settings. Delivery requires `CONTACT_ENABLED=true`, sender, recipient and a private API key. The key is stored as a Production secret. One real test was accepted, persisted as sent and confirmed in the owner's Gmail inbox. The initial own-inbox sender requires the Resend account to use the receiving email; sending to other recipients requires a verified domain.

The Python static development server does not execute Vercel functions. Use `npm run dev:cms` at port 4180 for the actual Node APIs and isolated development database. Existing frontend/API regression tests use controlled responses; separate CMS checks exercise real development Postgres and Blob. Contact persistence checks use real Postgres with a controlled mail transport and send no real emails. `qa/cms/CMS_VERIFICATION.md` distinguishes these results from live production and outstanding inbox verification.

`qa/sections-review.html` contains desktop/mobile screenshots, sampled entrance/return frames, and the browser recording for Journey, Resume, Contact and Notes. Refresh these with `node scripts/capture-sections.cjs` while the dev server runs. The objects deliberately transition from baked room pixels to readable interactive views; no seamless artwork match is claimed.

## Camera and rush effect

The selected A camera is now the only entrance: continuous movement with a brief approach, acceleration and a gentle landing. Entrance duration remains 560 ms on desktop and 420 ms on phones. The return is unchanged. The stepped B camera has been removed; old camera query parameters no longer select a different animation.

Six tapered pixel streaks (four on phones) travel outward from the projected monitor centre during the fast section, then fade before landing. The shared effect uses longer, thicker warm-white/cyan strokes and holds its peak brightness for about 110 ms on desktop / 84 ms on phones so it registers during a normal viewing. They remain at the edges, with no extra particles or landing flash. Their geometry is calculated once per entrance; the browser animates transforms and opacity. Reduced motion skips the camera and streaks together.

The former `/qa/camera-comparison.html` URL redirects to the selected studio. `?reference=1` is a localhost-only screenshot aid that freezes the approved first frame; normal navigation still captures the current live video frame.

## Validation and review

Run `npm ci`, `npm run test:unit`, then `npm test`. Playwright is the only development dependency. Tests use the installed Google Chrome browser (`channel: chrome`). The frontend regression server uses Python. No frontend framework build is needed. See `CMS_SETUP.md` for real database/upload integration checks and private environment setup.

`qa/review.html` shows the current smooth camera's browser recording and screenshots. Run `node scripts/capture-review.cjs` while the dev server is running to refresh `qa/smooth-rush-review.webm`.

`qa/about-review.html` shows the About Me entrance and return in dark and lit rooms, plus desktop, tablet and phone screenshots. Refresh its recording with `node scripts/capture-about.cjs`.

`qa/effect-review.html` compares the earlier and updated streak strength at matching Projects animation times, with desktop and phone frames and links to both current recordings.

Checks cover unchanged asset hashes, actual lighting playback, three shared cards, keyboard focus, Escape and browser history, deep-link refresh, empty/error/draft data, duplicate clicks, navigation and resizing during entry, reduced motion, and a native touch swipe. Camera checks sample rendered transforms, outward streak movement, edge placement and disappearance before landing. Screenshots cover 1440×900, 1920×1080, 768×1024 and 390×844, plus DPR 1.25 and 2. These DPR checks do not represent manually changing Chrome's toolbar zoom to 125%.

`qa/camera-timing.json` contains browser requestAnimationFrame samples. Screenshot runs deliberately pause the animation; only the final uninterrupted entry is appropriate for timing interpretation. Measurements describe this test host and browser, not a low-end device benchmark. The rendered frames and recording are provided for visual review; pixel perfection and a seamless handoff are not claimed.

For local calibration, open `/?calibrate=1`. Calibration outlines are disabled by default and unavailable on non-local hostnames. `?qa=1` exposes timing and read-only audio diagnostics only on localhost.
